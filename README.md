# ⚡ Бот графіка відключень світла (Тернопільобленерго)

Бере графік з відкритого API сайту [poweron.toe.com.ua](https://poweron.toe.com.ua) і веде **одне «живе» повідомлення** в Telegram:

| Що сталося | Що робить бот |
|---|---|
| Графік змінився (додали / прибрали відключення, з’явився графік на завтра) | Надсилає **нове** повідомлення: картинка + список змін (`🔴 додано відключення 22:00–24:00`) |
| Змін немає | **Редагує** попереднє повідомлення: оновлює картинку, час і напис «Змін немає ✅» |
| Сайт недоступний 3 перевірки поспіль (30 хв) | Один раз дописує попередження в підпис; коли сайт ожив, воно зникає саме |
| Ви видалили повідомлення в чаті | Бот надішле нове |

Перевірка — за замовчуванням кожні 15 хв (`CHECK_INTERVAL_SECONDS=900`); у GitHub Actions розклад запускається кожні 15 хвилин, але GitHub може затримувати фактичний старт. Картинка: сьогодні й завтра, плитки по годинах (половинка плитки = 30 хв), поточна година позначена «ЗАРАЗ», під плитками — проміжки з тривалістю.
🟢 світло є · 🔴 немає · 🟡 можливе відключення.

## Налаштування

**1. Встановіть залежності** (Python 3.10+):
```bash
cd toe_bot
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

**2. Створіть бота.** У Telegram відкрийте [@BotFather](https://t.me/BotFather) → `/newbot` → скопіюйте токен. Потім відкрийте свого бота й натисніть **/start** (так бот дізнається ваш чат).

**3. Дізнайтеся ключ адреси** (`TOE_ADDRESS` = `cityId/streetId/будинок`). Два способи:

* *Автоматично:* `python find_address.py "назва населеного пункту" "назва вулиці" --building "номер будинку"`. Скрипт покаже готовий рядок `TOE_ADDRESS=…`.
* *Запасний спосіб через DevTools* (1 хвилина): відкрийте сайт на комп’ютері → **F12** → вкладка **Network** → оберіть свою адресу й натисніть «Знайти» → у списку клацніть запит **`a_gpv_g`** → *Request Headers* → скопіюйте значення **`X-debug-key`** і вставте його в `TOE_ADDRESS` як є (це base64 від `cityId/streetId/будинок`; бот розуміє обидва формати).

**4. Заповніть `.env`:**
```bash
cp .env.example .env
```
Впишіть `TELEGRAM_BOT_TOKEN`, `TOE_ADDRESS`, свою підчергу `GROUP` та підпис `ADDRESS_LABEL`.

**5. Перевірте без Telegram:**
```bash
python bot.py --preview
```
У консолі з’являться проміжки відключень на сьогодні й завтра, а поруч — `preview.png`. Звірте їх із сайтом.

**6. Запустіть:**
```bash
python bot.py            # постійно (Ctrl+C — зупинити)
python bot.py --once     # одна перевірка й вихід
```

## Запуск 24/7

**Щоб бот працював завжди, незалежно від вашого комп’ютера й телефону, розгорніть його на сервері в хмарі — покрокова інструкція (VPS + Docker, Railway) у файлі [`DEPLOY.md`](DEPLOY.md).** Нижче — варіант без Docker, якщо в мережі вдома є пристрій, що працює постійно (міні-ПК, Raspberry Pi).

Приклад для Linux, `/etc/systemd/system/toe-bot.service`:
```ini
[Unit]
Description=TOE light schedule bot
After=network-online.target

[Service]
WorkingDirectory=/opt/toe_bot
ExecStart=/opt/toe_bot/.venv/bin/python bot.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```
`sudo systemctl enable --now toe-bot`. На Windows — «Планувальник завдань» із запуском при вході в систему.

## Параметри `.env`

| Змінна | Опис |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен від BotFather |
| `TELEGRAM_CHAT_ID` | необов’язково; якщо порожньо — бот візьме чат, де ви натиснули `/start` |
| `TOE_ADDRESS` | `cityId/streetId/будинок` або base64 з `X-debug-key` |
| `GROUP` | ваша підчерга, наприклад `5.1` |
| `CHECK_INTERVAL_SECONDS` | період перевірки, за замовчуванням 600 |
| `DELETE_PREVIOUS` | `1` — при новому повідомленні про зміну видаляти попереднє |

Стан (id повідомлення, останній графік) зберігається у `state.json`, лог — у `bot.log`. Щоб почати з чистого аркуша, видаліть `state.json`.

## Якщо щось не так

* **`--preview` пише, що графіка немає** — перевірте `TOE_ADDRESS` і `GROUP` (на сайті для вашої адреси має бути номер вашої черги). Графік на завтра зазвичай з’являється ввечері.
* **Не знайшло чат** — відкрийте бота й натисніть `/start`, потім запустіть знову.
* **Картинка без кирилиці / квадратики** — у `fonts/` мають лежати `Inter-*.otf` (вони там є).
* **Подивитися картинку без інтернету:** `python render.py` → `demo_nochange.png` і `demo_changed.png` (вигадані дані).


## Безкоштовний запуск через GitHub Actions (без постійного сервера)

У репозиторії вже є файл `.github/workflows/check-schedule.yml`. Він запускає `python bot.py --once` за розкладом `7,22,37,52 * * * *`. Це не 24/7-процес: GitHub періодично запускає коротке завдання, яке перевіряє сайт, оновлює Telegram і завершується. Час старту за розкладом може затримуватися.

### 1. Створіть Telegram-бота

У Telegram відкрийте [@BotFather](https://t.me/BotFather), виконайте `/newbot` і збережіть токен. Відкрийте створеного бота та натисніть `/start`.

### 2. Дізнайтеся ключ адреси

На комп’ютері встановіть Python 3.12+, відкрийте термінал у папці проєкту та виконайте:

```bash
pip install -r requirements.txt
python find_address.py "НАЗВА_НАСЕЛЕНОГО_ПУНКТУ" "НАЗВА_ВУЛИЦІ" --building "НОМЕР_БУДИНКУ"
```

Підставте назву свого населеного пункту, вулиці та номер будинку. Скрипт покаже `TOE_ADDRESS=...`; переконайтеся, що результат відповідає вибраній адресі на сайті. Якщо пошук не спрацює, відкрийте `poweron.toe.com.ua`, виберіть адресу, у браузері натисніть F12 → Network, знайдіть запит `a_gpv_g` і скопіюйте заголовок `X-debug-key`. Саме його значення і є `TOE_ADDRESS`.

Перед публікацією репозиторію перевірте локально:

```bash
# створіть .env на основі .env.example і внесіть токен та TOE_ADDRESS
python bot.py --preview
```

Увага: середовище розробки тут не має доступу до мережі, тому фактичний запит до API Тернопільобленерго ще не був перевірений. Виконайте `--preview` у себе та звірте результат із сайтом.

### 3. Створіть GitHub-репозиторій

Створіть репозиторій на GitHub і завантажте **вміст папки `toe_bot`**, а не саму зовнішню папку. Для безкоштовного використання стандартних GitHub-hosted runners можна зробити репозиторій public. Стан бота зберігається у файлі `state.enc` у зашифрованому вигляді; секрети не записуються в код. Не додавайте `.env` до репозиторію. Не вказуйте домашню адресу у відкритих файлах репозиторію; використовуйте секрет `ADDRESS_LABEL`.

### 4. Створіть секрети GitHub

У репозиторії відкрийте **Settings → Secrets and variables → Actions → New repository secret** і додайте п’ять секретів:

| Назва секрету | Значення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен від BotFather |
| `TELEGRAM_CHAT_ID` | ID вашого приватного чату з ботом |
| `TOE_ADDRESS` | Значення `cityId/streetId/номер` або base64 з `X-debug-key` |
| `ADDRESS_LABEL` | Підпис адреси, який буде показано на картинці |
| `STATE_ENCRYPTION_KEY` | Ключ шифрування, який створите командою нижче |

Згенеруйте ключ локально командою:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Скопіюйте результат у секрет `STATE_ENCRYPTION_KEY`. Зберігайте його: якщо втратити або змінити ключ, попередній зашифрований стан не відкриється, і бот створить нове повідомлення після відновлення стану.

Щоб дізнатися `TELEGRAM_CHAT_ID`, напишіть боту `/start`, потім відкрийте у браузері `https://api.telegram.org/botВАШ_ТОКЕН/getUpdates` і знайдіть `message.chat.id`. Не публікуйте URL із токеном і не надсилайте токен нікому.

### 5. Увімкніть автоматизацію

Відкрийте вкладку **Actions**, дозвольте запуск workflow, виберіть **Оновлення графіка відключень** і натисніть **Run workflow** для першого тесту. У разі успіху в Telegram з’явиться зображення. Далі GitHub запускатиме перевірку приблизно кожні 15 хвилин.

Файл `state.enc` комітиться назад у репозиторій у зашифрованому вигляді, щоб наступний запуск знав попередній графік та ID повідомлення. Не видаляйте його й не змінюйте ключ шифрування.

### Обмеження безкоштовного варіанта

- GitHub Actions schedule не є точним таймером: запуск може запізнитися, особливо під навантаженням.
- Для public-репозиторіїв стандартні GitHub-hosted runners безкоштовні; правила та ліміти GitHub можуть змінюватися.
- Якщо репозиторій неактивний 60 днів, GitHub може автоматично вимкнути заплановані workflows; перевіряйте вкладку Actions.
- Якщо сайт блокує запити з IP дата-центрів або повертає помилку, workflow не зможе отримати свіжий графік. Попередній графік залишиться, а помилка буде видна в логах.
- Не використовуйте токен бота в публічному коді, README або скриншотах.
