# Міграція з однокористувацького бота на публічного багатокористувацького

Інструкція розрахована на вже створений GitHub-репозиторій, де старий бот уже надіслав перше фото. Не створюйте нового Telegram-бота: використовуйте той самий токен і той самий репозиторій.

## Перед початком

1. Знайдіть у GitHub **Settings → Secrets and variables → Actions** секрет `STATE_ENCRYPTION_KEY`.
2. **Не видаляйте і не змінюйте його.** Новий код зможе прочитати старий `state.enc` тим самим ключем, визначить старий формат і створить нову структуру.
3. Переконайтеся, що секрет `TELEGRAM_BOT_TOKEN` залишається на місці.
4. Зробіть резервну копію старого `state.enc`, якщо хочете зберегти можливість повернутися до старої версії. Він містить зашифрований стан.

## 1. Замініть файли в локальній копії репозиторію

1. Завантажте й розпакуйте архів `toe_public_bot.zip` в окрему тимчасову папку.
2. Відкрийте папку вашого старого локального репозиторію `toe-light-bot`.
3. Скопіюйте **весь вміст** тимчасової папки в стару папку репозиторію, погодьтеся на заміну файлів.
4. Не копіюйте папку `.git` з архіву (її в архіві немає). Не видаляйте вашу папку `.git`.
5. Не копіюйте `.env.example` поверх реального `.env`; архів не містить реального `.env`.
6. Переконайтеся, що замінився `.github/workflows/check-schedule.yml`, а в корені є нові `bot.py`, `toe_api.py`, `telegram_api.py`, `render.py`, `config.py`, `state_store.py` і `requirements.txt`.

## 2. Відправте зміни в той самий GitHub-репозиторій

У PowerShell відкрийте стару папку репозиторію й виконайте:

```powershell
git status --short
```

Переконайтеся, що `.env` **не** відображається як файл для коміту. Якщо відображається — зупиніться, виправте `.gitignore` і не робіть push.

Потім:

```powershell
git add -A
git commit -m "Upgrade to public multi-user outage bot"
git push
```

Якщо Git повідомляє, що віддалений репозиторій має нові коміти, спочатку виконайте `git pull --rebase`, потім повторіть `git push`.

## 3. Перевірте GitHub Secrets

Відкрийте **Settings → Secrets and variables → Actions**. Для нової версії потрібні лише два секрети:

| Secret | Значення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | той самий токен від BotFather, який уже працював |
| `STATE_ENCRYPTION_KEY` | той самий Fernet-ключ, яким було зашифровано старий `state.enc` |

Секрети `TELEGRAM_CHAT_ID`, `TOE_ADDRESS`, `GROUP` та `ADDRESS_LABEL` більше не використовуються: кожен користувач сам вводитиме адресу в Telegram. Їх можна видалити після успішного запуску нової версії.

Не створюйте новий `STATE_ENCRYPTION_KEY`, якщо старий уже був доданий і використовувався. Новий ключ зробить старий `state.enc` нерозшифровуваним.

## 4. Дозвольте workflow записувати зашифрований стан

У репозиторії відкрийте **Settings → Actions → General → Workflow permissions** і виберіть **Read and write permissions**. Збережіть.

Це потрібно, щоб workflow міг записувати зашифрований файл `state.enc` назад у репозиторій після обробки команд та графіків.

## 5. Перший запуск після міграції

1. Відкрийте **Actions**.
2. Виберіть workflow **TOE public bot — users and outage schedules**.
3. Натисніть **Run workflow** на гілці `main`.
4. Перший запуск ініціалізує нову базу, пропустить старі тестові повідомлення Telegram і збереже новий зашифрований `state.enc`. Це зроблено, щоб давні `/start` або тестові фрази не були прийняті за адресу.
5. Дочекайтеся зеленого статусу всіх кроків. Переконайтеся, що в репозиторії оновився `state.enc`.

Після першого запуску відкрийте Telegram і надішліть боту `/start`. Перший запуск спеціально очищає чергу старих повідомлень, тому `/start` потрібно надіслати **після** нього.

У цей самий або наступний запуск workflow почне завантажувати повний публічний довідник адрес TOE в GitHub Actions Cache. Це може зайняти довше, ніж звичайна перевірка графіка (у довіднику багато сторінок). Кеш використовується для наступних користувачів, тож кожен новий користувач не запускає повне сканування повторно.

## 6. Перевірте підписку

У приватному чаті з ботом послідовно введіть:

1. `/start`
2. Назву населеного пункту, наприклад `Велика Лука`
3. Назву вулиці, наприклад `Івана Франка`
4. Номер будинку, наприклад `24`

Бот знайде адресу в довіднику Тернопільобленерго. Якщо знайдено кілька варіантів, він попросить вибрати номер варіанта. Після підтвердження підписка активується, а під час тієї ж або наступної перевірки надійде персональний графік.

Твоя адреса для прикладу має визначатися як `Велика Лука · вул. Івана Франка · 24`, черга `5.1`. Не потрібно більше вносити `22016/40637/24` у GitHub Secrets — користувачі підключаються самостійно.

## 7. Налаштуй команди в BotFather (необов'язково, але рекомендовано)

У чаті з `@BotFather` вибери `/setcommands`, вибери свого бота й надішли:

```text
start - підключити графік відключень
address - змінити адресу
status - моя адреса та черга
stop - вимкнути сповіщення
cancel - скасувати введення адреси
help - допомога
```

## 8. Як користуються інші люди

Надішліть їм посилання на вашого бота: `https://t.me/ВАШ_USERNAME_БОТА`. Кожна людина натискає Start та проходить власне введення адреси. Бот працює тільки в особистих чатах і не показує користувачам чужі адреси або підписки.

## 9. Якщо щось не працює

- **Workflow червоний:** відкрийте Actions → невдалий запуск → крок `Process Telegram users and refresh schedules`, прочитайте останню помилку.
- **Помилка розшифрування `state.enc`:** перевірте `STATE_ENCRYPTION_KEY`; відновіть саме попереднє значення, не генеруйте інше.
- **Немає права push:** встановіть `Read and write permissions` у Workflow permissions.
- **Бот не бачить команд:** перевірте, чи не встановлено webhook іншим сервісом; ця версія використовує `getUpdates` і при запуску видаляє webhook, не скидаючи pending updates.
- **Адресу не знайдено:** перевірте написання; підтримуються тільки записи з довідника poweron.toe.com.ua. Якщо список адрес оновився, очистіть GitHub Actions Cache з ключем `toe-address-index-v1-Linux` або змініть `v1` на `v2` у workflow, щоб індекс завантажився заново.
- **Команда не обробилася миттєво:** у безкоштовній конфігурації вона обробляється під час наступного запуску, орієнтовно протягом 15 хвилин.

## 10. Що означає «працює постійно» у безкоштовному варіанті

Бот не працює як безперервний процес. GitHub Actions запускає коротке завдання орієнтовно кожні 15 хвилин, читає Telegram updates, оновлює графіки й завершується. Точний час запуску не гарантується. Telegram зберігає необроблені updates не довше 24 годин. Заплановані workflow у публічному репозиторії можуть автоматично вимикатися після 60 днів без активності репозиторію; періодично перевіряйте вкладку Actions. Якщо сайт/API недоступний або змінить формат, у workflow будуть помилки, а останній успішний графік залишиться без підміни на «змін немає».
